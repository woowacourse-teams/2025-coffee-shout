# 디자인 토큰

구현은 [`src/styles/tokens.css`](../src/styles/tokens.css)에 있다. 이 문서는 **왜 그 값인지**만 적는다.

## 1. 색을 고르지 않았다

실제 유저가 보는 화면의 팔레트를 그대로 가져왔다. 백오피스가 자기만의 색을 가지면 같은 서비스의 두 화면이 다른 제품처럼 보인다.

| 출처 | 가져온 것 |
| --- | --- |
| `frontend/src/styles/theme.ts` | `color.point`(브랜드 6단계), `color.gray`(11단계), `color.blue`, `color.status.online`, `color.yellow`, `color.oauth` |
| `frontend/src/constants/color.ts` | `colorList`(레이싱 게임 플레이어 색), `tierColorMap.GOLD` |
| `admin-web/public/brand/logo.svg` | 워드마크 `fill="#FD6C6E"` |

**로고 색 `#FD6C6E`는 서비스 테마의 `point-400`과 같은 값이다.** 브랜드 스케일이 이미 서비스 안에 있었으므로 별도 코랄 스케일을 만들 필요가 없었다.

## 2. `#FD6C6E`를 액션 색으로 쓸 수 없는 이유

| 조합 | 대비 | 판정 |
| --- | --- | --- |
| 흰 배경 위 `point-400` 텍스트 | **2.78:1** | AA 본문(4.5) 실패, 큰 텍스트(3.0)도 실패 |
| `point-400` 채움 위 흰 텍스트 | **2.78:1** | 실패 |
| `point-500` `#F53E41` 채움 위 흰 텍스트 | 3.72:1 | AA 실패 |

계산 결과다. 키 컬러는 **틴트 배경, 액티브 인디케이터, 포커스 링, 선택 상태**로 간다. 브랜드색 텍스트가 필요한 자리를 위해 서비스 스케일에 없는 `point-600 #D42A2D`(5.04:1)와 `point-700 #B02023`(6.83:1)을 같은 색조로 확장했다.

## 3. 역할 배치

| 역할 | 값 | 출처 |
| --- | --- | --- |
| 아이덴티티 | `point-400 #FD6C6E` | 서비스 |
| 액션 (Primary, 사이드 레일) | `gray-900 #101828` | 서비스 |
| 상태 신호 | 초록 / 노랑 / 파랑 / 빨강 | 서비스 값 기반 |

### 검증된 조합

| 조합 | 대비 | 판정 |
| --- | --- | --- |
| Primary 채움(`gray-900`) + 흰 텍스트 | **17.75:1** | AAA |
| 다크 레일 흰 텍스트 | 17.75:1 | AAA |
| **브랜드 로고 on 다크 레일** | **6.38:1** | AA |
| danger 채움 + 흰 텍스트 | 5.74:1 | AA |
| danger vs Primary 구분 | 3.09:1 | 통과 |
| success 채움 + 흰 텍스트 | 5.39:1 | AA |
| warning 텍스트 on warning 배경 | 5.03:1 | AA |
| info 채움 + 흰 텍스트 | 4.83:1 | AA |
| 본문 텍스트 on 캔버스 | 16.98:1 | AAA |
| 보조 텍스트 on 카드 | 7.56:1 | AAA |

세 번째 줄이 중요하다. 레일을 `gray-900`으로 두면 **브랜드 로고를 원래 색 그대로 올릴 수 있다.** 화이트 버전 로고를 따로 만들 필요가 없다.

## 4. 서비스 값을 그대로 못 쓴 세 곳

서비스 팔레트는 소비자 화면 기준이라 백오피스의 채움 버튼 용도로는 대비가 모자란 값이 있다. 색조는 유지하고 명도만 낮췄다.

| 자리 | 서비스 값 | 백오피스 값 | 이유 |
| --- | --- | --- | --- |
| danger 채움 | `red #FF0000` | `#C81E1E` | 서비스 값은 흰 텍스트 4.00:1로 AA 미달 |
| success 채움 | `status.online #1FCD7E` | `#0E7A49` | 서비스 값은 2.08:1. 원래 값은 점과 아이콘으로만 남김 |
| warning 텍스트 | `tierColorMap.GOLD.text #9A6B00` | `#8A6000` | GOLD 배경 위 4.21:1로 AA 미달 |

## 5. Primary와 Danger

`gray-900`이 액션 색이 되면서 danger 빨강과 색조가 완전히 갈린다(구분 3.09:1). 색만으로도 구분되지만, 기본형은 **표 안에서 아웃라인, 확인 다이얼로그에서 채움**으로 둔다.

접근성 때문이 아니라 **밀도** 때문이다. 표의 모든 행에 빨간 채움 버튼이 있으면 화면이 경고로 뒤덮여 진짜 경고가 안 보인다.

## 6. 차트 팔레트

서비스 `colorList`(레이싱 게임에서 플레이어를 구분하는 색)의 **색조를 유지하고 명도만 낮춘** 6색이다. 원본은 소비자 화면의 큰 면적용이라 밝은 캔버스 위 얇은 마크로는 대비가 모자랐다.

| 슬롯 | 값 | 서비스 원본 |
| --- | --- | --- |
| 1 | `#F53E41` | `point-500` (브랜드) |
| 2 | `#3A6BB0` | `#5a88c8` |
| 3 | `#0F9E7A` | 서비스 초록 계열 |
| 4 | `#C97A00` | `#ffa102` |
| 5 | `#9B4FE0` | `#bf77f6` |
| 6 | `#5E8A1A` | `#85b62e` |

dataviz 검증기 **전 항목 통과**. 최악 인접쌍은 protan ΔE 10.4, 정상 시야 ΔE 19.5로 목표치(8, 15)를 넘긴다.

규칙 두 가지.

- **순서를 고정한다.** 계열을 순환시키거나 필터 결과에 따라 다시 칠하지 않는다. 색은 항목에 붙지 순위에 붙지 않는다.
- **상태 색은 차트 계열로 쓰지 않는다.** 초록이 "성공"과 "3번 계열" 두 뜻을 가지면 볼 때마다 문맥을 따져야 한다.

소셜 제공자 분포 차트는 예외로 서비스 `theme.color.oauth` 값을 고정 사용한다. 제공자 색은 브랜드 자산이라 계열 순서와 무관하다.

## 7. 타이포그래피

| 용도 | 폰트 | 근거 |
| --- | --- | --- |
| 본문, UI | Pretendard Variable | 서비스 프론트가 쓰는 폰트와 동일 |
| 숫자, ID, joinCode, 로그, JSON | JetBrains Mono | 기존 백오피스(`static/css/admin.css`)가 쓰던 폰트를 이어받음 |

본문 기본 **13px**. 어드민은 정보 밀도가 미덕이라 소비자 앱의 여백 기준을 따르지 않는다. 전역 `tabular-nums`로 표에서 자릿수가 흔들리지 않게 한다.

## 8. 그림자보다 경계선

표가 많은 화면에서 그림자는 노이즈다. 층위는 1px 경계선과 배경 톤 차이로 만들고, 그림자는 **실제로 떠 있는 것**(드롭다운, 다이얼로그)에만 쓴다.

## 9. 컴포넌트는 역할 별칭만 참조한다

`--point-400`을 직접 쓰지 않고 `--accent`, `--rail-indicator`처럼 역할 이름을 쓴다. 팔레트가 바뀌면 별칭 블록만 고치면 된다.

## 10. 알려진 제약

`character.svg`는 SVG 껍데기 안에 1000x1000 PNG가 base64로 박힌 형태다(76KB). 진짜 벡터가 아니라서 1000px을 넘겨 확대하면 깨지고 `currentColor`로 색을 바꿀 수 없다. 파비콘(32px), 레일 아바타(24-32px), 로그인 화면(약 120px) 용도에는 문제없다.

**다크 모드는 구현하지 않는다.**
